# Portfolio KPI Reporting Automation

> **All data in this repository is SYNTHETIC.** The five portfolio companies, their figures, files and "analyst resubmissions" are fictional and generated by `data_gen/generate.py`. Nothing here is real financial information.

**Live demo:** _add your Streamlit URL here_ | **Demo video:** _add link_

Monthly reports from five portfolio companies arrive in different formats, with different names for the same KPI, different units and currencies, and columns that move between months. This pipeline ingests them, maps them to one KPI schema, normalizes them, checks data quality with rules a non-engineer can edit, reconciles the fund rollup, and produces an LP/board report in which every number traces to its source file and cell.

## Architecture

```mermaid
flowchart LR
  A[Raw files<br/>CSV / Excel (merged cells) / PDF] --> B[Ingest<br/>raw cells + file/cell provenance]
  B --> C{Mapping}
  C -->|saved & approved| E
  C -->|new label| D[rapidfuzz -> LLM suggestion<br/>validated, never auto-saved]
  D --> H[Human confirms once<br/>saved to config/mappings]
  H --> E[Normalize<br/>units - fixed FX - fiscal period<br/>analyst corrections kept with original]
  B --> F[Schema drift log]
  E --> G[Data-quality rules<br/>YAML, fail / warn]
  E --> R[Rollup + reconciliation]
  G --> X{Gate}
  R --> X
  X -->|open failures| Y[BLOCKED<br/>exceptions list]
  X -->|clean| M[Metrics in pandas<br/>display string + source cells]
  M --> L[LLM writes placeholders<br/>code fills figures, re-verifies]
  L --> P[PDF report + Streamlit app]
```

| Stage | Result | Notes |
|---|---|---|
| Ingest | 30 files (CSV / Excel with merged cells / PDF) -> 222 raw cells, each with file + cell location | all parsed; revenue cell matches ground truth for 29/30 (the 30th is the planted 10x typo) |
| Column mapping (shipped labels) | 33/33 labels mapped to the right KPI | 32 near-exact matches bulk-confirmed, 1 label approved by hand |
| Column mapping (held-out labels) | 23 unseen labels incl. 6 non-KPIs: 0 wrong auto-accepts, true KPI in top-3 for 17/17 | only 1/23 auto-accepted - fuzzy handles near-exact labels, the rest need LLM + human |
| Schema drift | 13/13 injected reorders detected, 0 false alarms, 1/1 rename detected | revert months are flagged too, by design |
| Normalization | 0/192 facts deviate from ground truth after corrections | before corrections 5 deviate: exactly the planted cells; tolerance = half the last digit each company reported |
| Data-quality rules | 5/5 planted errors caught at 'fail' severity; 0 stray company-months flagged | 7 violations in total; 0 after corrections |
| Reconciliation | 6/6 checks pass over 435 items | fund = sum of companies, every fact re-derived from its raw cell, no partial sums |
| Gate | raw submissions -> BLOCKED_DQ; after corrections -> FINAL | without the gate, fund churn would have shown 20.3%; correct value is 1.7% |
| LLM commentary check | 17 figures verified, 0 unmatched; correct figures accepted 40/40 | post-filter alone wrongly accepted 20/160 perturbed figures; in placeholder mode literal numbers typed by the LLM are rejected 80/80 |
| Pipeline runtime | 2.923s mean end-to-end over 5 runs (max 3.07s), 30 files | ingest 0.59s, reconcile 0.191s, pdf 0.921s |

Known limitation measured: the checker verifies that a figure exists in the data, not that it is attached to the right label. Swapping real fund-level dollar figures between labels was wrongly accepted in 70/70 cases. That is why the LLM writes metric placeholders instead of numbers: it can still pick the wrong metric id, but it can no longer invent, round or mistype a figure.

Manual baseline (Excel) and the speed-up are NOT measured here. See docs/MANUAL_BASELINE.md.


## What is deliberately conservative
- **Fail closed.** Unapproved column labels stop the run (`NEEDS_MAPPING`); open `fail` data-quality exceptions stop the report (`BLOCKED_DQ`). The warning-only path never blocks.
- **No guessing units.** Currency and unit come from each file's own note line; a file without one is an error.
- **No partial sums.** If a company is missing a KPI in a month, the fund figure is blank and marked incomplete.
- **The LLM never produces a figure.** It writes `{metric_id}` placeholders, the code substitutes the pandas-computed display string, any literal digit typed by the model is rejected, and the final text is re-checked against the data. Without an API key, or if the model fails, a deterministic template is used and labelled as such.
- **Corrections keep the original.** Analyst corrections are applied to the native value with the original, reason and approver stored and shown in the report.

## Failure analysis (what went wrong while building this, and what is still weak)
1. **My first mapping evaluation was circular.** I had put the dataset's own labels in the synonym list, so everything scored 100. A held-out set of 23 unseen labels (including non-KPIs like Net Income and Capex) is the real measure, and it shows fuzzy matching alone auto-accepts only 1 of 23.
2. **A percent guard I wrote excluded valid matches** ("Logo Churn" matched `cash`) and the auto-accept threshold equalled `WRatio`'s cap for substring matches (90). Fixed: one-directional guard, threshold 95.
3. **The validators caught bugs in my own generator**: fiscal labels `FY26 M13` (should be `FY27 M1`), string `hash()` making the column shuffle non-deterministic, and unrealistic month-to-month headcount noise that produced four false-positive warnings. I fixed the data rather than loosening the rule.
4. **A month-on-month rule double-flags a spike** (the correct month after a 10x typo looks like a crash). Fixed with spike-and-revert suppression.
5. **`None` vs `NaN`.** A pandas column turned a missing currency into `NaN`, so my "refuse to guess" guard did not fire. A test caught it.
6. **The post-hoc number checker is weak on its own**: it wrongly accepted 20/160 perturbed figures (a wrong number can equal another real metric) and 70/70 label swaps (a real number under the wrong label). That is why the design changed to placeholders. Remaining risk: the model can choose the wrong metric id.

**Not covered / limits you should state in an interview**
- Synthetic files are cleanly structured: one period per file, one header row. Real reports have many rows, sheets and periods, so ingest accuracy here is overstated. The PDFs are generated, so there is no OCR path for scanned PDFs.
- `GroqResolver` and `GroqCommentary` are unit-tested with stubs only. They could not be called from the build sandbox (no network), so verify one live call with your key.
- The shipped mappings were bootstrapped by `scripts/bootstrap_mappings.py` (32 auto-confirmed, 1 approved by hand), not reviewed by a finance user.
- One fixed FX table (no distinction between average and closing rates). Fiscal handling covers a configurable year-end month only.
- "ARR-weighted churn" is my definition for the fund-level figure.
- The manual-vs-pipeline ROI is not in the table because it must be measured by a person: see `docs/MANUAL_BASELINE.md` and `roi.py`.

## Run it
```bash
pip install -r requirements.txt
make data mappings        # synthetic files, ground truth, approved mappings
make test                 # 80+ tests
make raw                  # raw submissions -> BLOCKED (exit 3)
make final                # with analyst corrections -> FINAL + PDF
make app                  # Streamlit (scenario toggle in the sidebar)
make evaluate             # regenerates the results table above
```
Optional: `export GROQ_API_KEY=...` to enable LLM suggestions for ambiguous labels and LLM-written commentary.

## Layout
`data_gen/` synthetic data + ground truth | `ingest/` readers | `mapping/` matcher, LLM resolver, store, confirm CLI | `normalize/` | `quality/` YAML rules engine | `drift/` | `reconcile/` | `report/` metrics, commentary, PDF | `config/` FX, rules, synonyms, saved mappings | `app.py` | `pipeline.py` | `evaluate.py`
